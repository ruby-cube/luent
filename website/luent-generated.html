Build interfaces from live state, not render loops.

Luent keeps the mental model narrow: wire observable values to DOM structure, derive what needs to change, and let the runtime update only the parts that matter.

Guide for app authors
Focus ions, bindings, and effects

Atomic Ions

An ion stores a value that can be observed directly by templates, effects, and derived state. Instead of re-running a whole component tree, Luent can push a precise update into the exact binding that depends on that value.

Reach for ions when a value is expected to change over time and the UI should react immediately. They are the smallest unit of interactivity in the system.

Direct subscriptions

DOM bindings can listen to a single source without involving a full component rerender.

Composable updates

Derived values and effects can build on ions without introducing a separate state layer.

Derivations

Derived state lets you express relationships without duplicating data. When upstream inputs change, the dependency graph updates the article, list item, or attribute that depends on them. 

const count = ion(0)
const label = derive(() => `Clicks: ${count()}`)

button.textContent = label()
button.onclick = () => count(count() + 1)

effect(() => {
  document.title = label()
})

The article body can stay declarative while low-level DOM work remains explicit. That balance is what gives Luent its fast feel without forcing everything into a component abstraction.

Bind structure close to the DOM

Text nodes, attributes, event handlers, and conditional regions can all be wired directly. This keeps the code close to the thing it changes, which makes debugging and progressive enhancement noticeably simpler.

Components stay lightweight

Components are useful for organization, but they are not the only way to achieve reuse. Luent leans on functions, templates, and bindings so you can extract patterns without building a deep component hierarchy.

Effects are for coordination

Effects belong at the edges: analytics, imperative widgets, timers, and browser APIs. They are easiest to reason about when they coordinate already-derived state instead of computing business logic themselves.

Async rendering without losing the thread

Async work can flow into the same reactive graph. The UI does not need a separate mental model for loading, settled, and refreshed states if those states are expressed as regular values.

Shape the app around flows

Organize code around data flow and user interactions rather than forcing every feature into one folder shape. This docs layout keeps navigation stable while making room for long-form explanations, worked examples, and API references.
